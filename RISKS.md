# Risks

Risk and security review of the changes planned on 2026-10-27, after the E07 eval (`tests/eval_baselines/seller-20261025T193317Z.txt`) and the user's scores of it. For the user to analyse. Open points still go to `RECHECK.md`.

## Invariants no change may break

1. The buyer's chat never reaches the chat's LLM (`classify`) or Tavily while `awaiting` is `"chat"` or `"consent"` (test_c05, extended; C35).
2. Every word the seller reads is written by code, by a verified note quoted word for word, or by PayPal. The LLM only picks closed choices. Since 2026-10-28, one exception: a follow-up's answer step writes 1 to 3 sentences, each citing sentences of verified notes. It is shown only if `output_guardrails.check_answer` passes every sentence; otherwise the notes are quoted, and the reply points to PayPal or, on the demo, offers a person (2026-10-31). Since 2026-10-30, on the demo, a second exception: an operator's answer to a handoff, written by a person and shown apart, as "Operator: …".
3. Only `verdict_for` decides the verdict. Context never gives VERIFIED to a new payment.
4. The new state fields can't be written through the input (`input_schema=MessagesState`). The `START` router doesn't read them, since it sees the raw input.
5. A node writes only what its `@owns` lists.
6. Tavily gets only the current message, cleaned by `_query()`, never the context.

LLM cost per message: classify is one call. A follow-up answered by the notes just shown makes a second, the answer step (about 1,000 tokens), so the demo's "message" rate limit counts up to two Groq requests per message.
